# 보안 수정 및 구조 정리

## 적용 내용

1. Next.js 15.5.28, sharp 0.35.5로 패치하고 오래된 sharp 강제 설정을 제거했다. Next.js의 PostCSS는 패치 버전으로 override했다. npm 설치 후 audit 결과는 전체 의존성 0건이다.
2. 모든 AI API에 공통 인증·입력 검증·분산 사용량 제한을 적용했다. JSON 스트림은 7 MiB, 이미지 원본은 5 MiB까지다. base64와 MIME별 파일 시그니처를 확인하고, 메시지·아이템·최근 기록의 타입과 길이·개수도 제한한다. 시그니처 검사는 이미지 전체 디코딩 검증과는 다르다.
3. 브라우저 초대 표시와 서버 인증 모듈을 분리했다. 로그인 후 프로필 판정과 라우팅을 통합하고 `next`는 허용한 내부 경로만 받는다.
4. 온보딩 상태·임시 사진·AI 전송 동의·추천 캐시를 사용자별로 분리했다. 소유자를 알 수 없는 이전 공통 임시 데이터는 폐기하며 착장 기록은 유지한다. 로그아웃·계정 변경 시 임시 데이터를 정리하고 계정 삭제 시 해당 계정의 로컬 데이터를 제거한다.
5. iOS Supabase 세션은 SecureStorage의 Keychain을 사용한다. 기존 평문 세션은 읽을 때 Keychain 저장 성공 후 제거한다. iCloud 동기화를 끄고 기기 전용 접근 속성을 사용한다. 웹은 기존 localStorage 인증을 유지한다.
6. API 클라이언트는 자체 origin의 `/api/`만 허용한다. 주소 검증 후 토큰을 읽으며 리다이렉트를 따라가지 않는다.

Home의 날씨 처리, 스타일 통계와 추천 캐시를 분리했다. Closet의 카테고리 모델·목록 UI·계정 삭제와 공유를 분리하고, 업로드의 날씨 상태를 별도 hook으로 옮겼다. 빈 start.py와 미사용 목업을 제거했으며 실제 온보딩 선택지는 onboarding-options.ts로 이동했다. 타임라인은 다른 사람의 샘플 사진 대신 첫 기록 안내만 보여준다.

## 서버 설정

AI 기능을 사용하려면 서버에 `UPSTASH_REDIS_REST_URL`과 `UPSTASH_REDIS_REST_TOKEN`을 설정해야 한다. EVAL을 지원하는 Redis REST 서비스에 연결한다. 설정이 없거나 연결에 실패하면 AI API는 503을 반환한다. 인메모리 제한으로 우회하지 않으므로 서버리스·다중 인스턴스에도 동일한 제한이 적용된다.

기본 한도는 사용자당 분당 6회·UTC 일일 60회·동시 2개, 전체 동시 20개·UTC 일일 1,000회다. 전체 일일 한도는 `AI_GLOBAL_DAILY_LIMIT`으로 변경한다. 한도 초과 시 429와 Retry-After를 반환한다. 잘못된 입력도 호출 한도에 포함된다. 요청 실패 시 일일/분당 할당량은 복구하지 않고 동시 실행 슬롯만 해제한다. 프로세스 장애 시 슬롯은 90초 후 만료된다.

사진 분석은 최대 2개 모델을 각 1번 호출한다. SDK 자체 재시도는 비활성화했고 외부 호출당 타임아웃은 25초, 출력 토큰은 분석/추천 2,048·문의 1,024로 제한했다. 일일 한도는 요청 수이며 금액 한도는 아니다. 실제 결제 예산은 Gemini 제공자의 결제·할당량 설정도 적용해야 한다.

계정 삭제에는 기존 `SUPABASE_SERVICE_ROLE_KEY`, 모바일 연결에는 실제 HTTPS `NEXT_PUBLIC_API_ORIGIN`이 필요하다. 서버용 키는 NEXT_PUBLIC로 노출하면 안 된다.

## 검증 범위

보안 회귀 테스트는 리다이렉트, 토큰 목적지, 잘못된 JSON/이미지/채팅, 스트림 크기 제한, 사용량 제한 장애 및 거부 응답, 계정 전환·삭제 시 데이터 분리를 다룬다. Redis REST 응답은 테스트에서 모의 처리하므로 실제 Redis 연결과 부하 검증은 운영 설정 후 수행해야 한다.

최신 Xcode에서 Keychain·카메라·공유·계정 전환을 실제 기기로 확인해야 한다. 현재 머신은 Xcode 15.4라 네이티브 실행 검증은 남아 있다. Supabase 실제 RLS·Storage 정책은 원격 프로젝트 접근이 없어 검증하지 않았다.
