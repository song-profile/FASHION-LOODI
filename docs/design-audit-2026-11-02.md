# LOODI 디자인·기능 점검 — 2026-11-02

현재 앱을 크림 바탕, 버건디 버튼, 올리브 포인트의 사진 중심 패션 저널로 다듬었다. 기존 작업 파일을 유지하며 수정했다. **피그마 파일/프레임 URL이 제공되지 않았고 저장소에도 없어, 피그마 원본 가져오기와 원본 대조는 아직 수행하지 않았다.** 아래 시안은 기존 프로젝트의 이미지와 컴포넌트로 구현한 화면이다.

시안은 격리된 Playwright 브라우저에 샘플 기록을 넣어 캡처했다. 실제 계정이나 개인 기록을 수정하지 않으며, 운영 앱에 샘플 데이터를 삽입하는 코드도 추가하지 않았다. 샘플 사진은 저장소에 있던 브랜드 이미지다.

## 보완한 부분

| 영역 | 확인한 문제 | 변경 내용 |
| --- | --- | --- |
| 홈 | 정보가 카드에 반복되고 첫 동작의 구분이 약함 | 브랜드 사진과 타이포그래피, 기록 CTA, 실제 기록 통계, 추천 영역 정리 |
| 화면 전환 | 화면 등장 스타일이 적용되지 않음, 고정 요소와 스크롤 여백 충돌 | 짧은 opacity 전환, reduced-motion 지원, 하단 메뉴 선택 상태 및 스크롤 여백 보강 |
| 상세 창 | 페이지 내부에 고정 창이 포함되어 전환 효과와 겹칠 수 있음 | body portal로 분리, 독립 스크롤, 닫기/삭제 터치 영역, 사진 확대 |
| 기록 | 오늘 날짜만 저장 가능 | 과거 날짜 선택, 달력의 선택 날짜에서 기록 진입, 저장 후 해당 달로 이동 |
| 작성 중 이동 | 새로고침·뒤로 가기에서 입력 소실 | 사용자별 sessionStorage 임시 저장, 사진·메모·분석·날짜 복원, 새로 쓰기. 탭 종료/로그아웃 후 보존하는 영구 저장은 아님 |
| 수동 기록 | 분석 없이 저장하면 스타일 입력 불가 | 태그와 컬러 직접 입력, 스타일 분석 반영 |
| 룩북 | 작은 사진과 날짜 이동/검색 부족 | 2열 사진 룩북, 검색·초기화, 사진 달력, 이전/다음 달·오늘 버튼 |
| 스타일 분석 | 영어 스타일 태그가 인식되지 않거나 계절이 스타일로 분류됨 | 홈과 DNA에서 동일 집계 사용, 명시적 스타일 태그 우선, 계절을 스타일로 분류하지 않음 |
| 컬러 | Light Blue가 Blue보다 먼저 분류되지 않음 | 구체적인 컬러 이름 우선 매칭 |
| 옷장 | 빈 카테고리가 화면을 반복 점유 | 카테고리 필터, 실제 아이템이 있는 목록 우선 표시, 빈 상태의 기록 연결 |
| 데이터 보관 | 기기 로컬 기록에 백업 경로 없음 | JSON 내보내기·미리 확인·복원, 기존 편집 보존, 중복 방지, 파일 형식/크기 검증 |
| 데이터 오류 | 손상된 저장소가 빈 기록으로 취급된 뒤 덮어써질 수 있음 | 추가/수정/복원 전 검증, 오류 시 기존 저장 데이터 유지 |
| 프로필 | 원본 사진을 그대로 저장하고 저장 실패를 알리지 않음 | 사진 압축·크기/타입 제한, 저장 실패 표시, 이전 사진 유지 |
| 공유 | 공유 API가 없거나 실패해도 완료처럼 끝남 | 지원 불가/실패 알림, 사용자의 공유 취소는 정상 처리 |
| 레벨 | 구현되지 않은 PDF·추천 횟수 혜택 안내 | 실제 기록 날짜에 따른 성장 문구로 수정 |
| 추천 | 날씨 요청 중에는 추천 불가, 중복/이탈 요청 처리 부족 | 날씨 없이도 추천 요청 가능, 중복 방지·이탈 취소·60초 제한 |

## 아직 완료되지 않은 부분

| 항목 | 현 상태 / 필요한 작업 |
| --- | --- |
| 피그마 원본 반영 | node-id가 포함된 원본 화면 링크 필요. 현재 시안은 원본을 가져온 결과가 아님 |
| 운영 AI API | 로컬 UI 테스트는 모의 AI 응답 사용. 실제 서버 주소와 Redis 설정 후 실제 계정으로 분석·추천·문의 검증 필요 |
| 계정 삭제 | 서버 코드는 있으나 `SUPABASE_SERVICE_ROLE_KEY`가 없어 운영 삭제 미검증 |
| 자동 기기 간 동기화 | 미구현. 이번에 추가한 것은 사용자가 파일로 옮기는 백업·복원이며 자동 클라우드 동기화가 아님 |
| 공개 프로필 링크 | 미구현. 현재 공유는 소개 텍스트이며 다른 사용자가 기록을 열어보는 공개 페이지는 아님 |
| 월간 PDF 리포트 | 미구현. 제공되는 혜택처럼 표시하던 문구 제거 |
| 계정 복구 | 비밀번호 재설정 흐름 미구현. 현재 아이디를 내부 이메일로 변환하는 가입 구조에서 실제 복구 수단 결정 필요 |
| iOS 빌드·기기 검증 | 로컬 출시 점검에서 Xcode 26+ 및 iOS SDK 미충족. 카메라·공유·파일 백업·키보드·뒤로 가기 제스처 실기기 검증 필요 |
| 출시 준비 | 개인정보처리방침·운영자 연락처·정식 아이콘·스토어 자료·서명 설정 필요. 운영자 정보를 임의로 생성하지 않음 |

`npm run release:check`에서 확인된 미설정 항목: `NEXT_PUBLIC_API_ORIGIN`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `SUPABASE_SERVICE_ROLE_KEY`, Xcode 요구사항. 키의 값은 문서나 테스트 출력에 기록하지 않았다.

## 검증 방법과 한계

최종 코드 기준 웹 빌드·TypeScript 검사 통과, 단위 테스트 **14개 통과**, 브라우저 테스트 **18개 통과**, `git diff --check` 통과. 최종 시안도 같은 빌드에서 다시 캡처했다.

- `npm run build`: 프로덕션 빌드와 타입/린트 검사.
- `npm run test`: 백업·복원·잘못된 데이터·스타일 분류·인증 경로·사용량 제한 등의 단위 검사.
- `npm run test:ui`: 일반 휴대폰, 320×568 작은 화면, 1280×800 데스크톱의 Chromium 흐름 검사. 가입, 설문, 추천, 기록, 수정/삭제, 프로필, 문의, 임시 저장, 백업 복원 포함.
- 실제 로컬 서버의 4개 API에 대해 미인증 요청 401과 iOS CORS preflight 검사. 유효한 사용자로 AI 호출이나 계정 삭제를 실행한 검증은 아님.
- `npm run test:ui -- tests/e2e/preview.spec.ts --project=phone`: 샘플 데이터로 구현 화면 5개와 시안 보드 생성.

브라우저의 인증·AI·날씨는 모의 응답이다. 이 결과는 운영 서비스 연결, 실제 iOS WebKit/네이티브 동작, 배포 또는 출시 완료를 의미하지 않는다.
